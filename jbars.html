Copper Bars: Palette Cycling 101

This is the first one of my own files, and you'll want to have a look at the code itself at the very bottom. I had an unfortunate habit of minification, so this program is really just one of the Centerpoint samples from entry 01, stripping out the advertisement, and then renaming everything to single character names and removing all unneeded whitespace. I'm not sure how much I really understood of the code at this time.

the 256 DAC registers: 1–180 are the 180 scanlines.

What it does

The screen is painted once, at startup: scanline n is filled entirely with color index n+1, 180 rows of 320 identical bytes. After that not one pixel is ever written again. The bars move because the program rewrites DAC registers, and because each register owns exactly one scanline, changing register 60 repaints row 59 and nothing else.

Per frame the original issues four bars × 90 = 360 OUT instructions and touches zero video memory. On a 386 that is free, which is the whole reason the technique existed. It is also the technique that ties this archive together: seven of the seventeen programs here write no pixels at all after setup.

Where it came from

Back on entry 01 you'll find everything about the original inspiration.

What I did to it

JBARS is a transcription of PALETTE2's DoCycle, instruction for instruction, with the labels Wait / Retr / BarLoop / PrevIsLast / Continue1 / Rep1 renamed to k / n / o / j / d / p. Identifiers go to single letters, hex is converted to decimal ($3C8 → Port[968], MOV DX,3DAh → MOV DX,986, VideoMode($13) → r(19)), and every constant expression is folded by hand: Locs[(NumCycles-1)*2] becomes l[398], MOV CX,15*3 becomes MOV CX,45, and Round(Radius*Sin((2*Pi/NumCycles)*Count))+Radius+1 becomes Round(g*Sin(0.0314*b)+81).

That last one is the only substantive change in the file. 2π/200 is 0.031416, and I had 0.0314, a truncation, so the sine table drifts about half a row short of a full period over its 200 entries. You cannot see it; it is just the one place where the transcription stopped being exact.

The notch

Watch two bars cross and the lower one loses a slice. The loop handles bars one at a time - blank fifteen registers at this bar's previous position, then write the gradient at its current one - so a bar that has already been drawn can be partly erased by the next bar's blanking pass. The checkbox rebuilds the whole palette instead, clearing every register before drawing any bar, which removes the notch. That is not what the file does, and at four bars ten rows apart you rarely catch it. Nietzche's original has it too.
