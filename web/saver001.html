Mixing It Up

This is the end of the archive, and one of my favorites. Nothing is new, but I figured out I could use the classic bouncing lines screensaver to make a nice plasma target, so it brings a few earlier tricks together nicely.

Being able to go through all this old code and see it running again has been quite a trip. I hope someone finds it interesting, whether to inspire their own version, or to learn more about these coding techniques (I barely scratch the surface), or even just to look at the visuals.

Thanks for visiting!

the palette history buffer d[1..256]
random(33)+30 is re-rolled every frame, so each channel turns around somewhere between 30 and 62 rather than at a fixed point -- and, crucially, the three channels stop moving in lockstep.
The .BAK bound is a constant 63 for all three channels. r, g and b start at 0 with the same step direction and identical limits, so they stay exactly equal forever: the whole screensaver is grayscale. That is what the one-line change on 2 Sep 1996 fixed.

Color as a clock

A bouncing line whose color comes from a 256-entry rolling history buffer. The index encodes when a segment was drawn, not where it is, so a wave of color travels along the scribble in the order it was laid down. You are watching the drawing's own history play back through the palette.

It is the same idea as PLASMA's walker from thirteen months earlier, pointed at something better suited to it.

The one-line fix, eleven months late

The only difference between .BAK and .PAS fixes a bug that had been sitting in ALL's P2 since September 1995: r, g and b start equal with equal bounds, so they never diverge and the whole thing is grayscale. random(33)+30 breaks the tie.

What makes this the right file to end on is the shape of it. P5, eleven lines below P2 in the same file, always had the answer. So did PLASMA.PAS in July 1995, which never had the bug at all. The fix took eleven months to travel eleven lines, and then it is the last thing I wrote.

Two things left in it

The palette loop writes register 256, which wraps to 0, so the newest color lands on the background. And 1024 port writes will not fit in one vertical blank, so on the hardware it was written for the palette update tore. Neither is fixed here; both are what the file does.
